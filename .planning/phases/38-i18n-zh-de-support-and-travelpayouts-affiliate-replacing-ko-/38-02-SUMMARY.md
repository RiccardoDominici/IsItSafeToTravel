# Phase 38 Plan 02: Wire zh and de pages, sitemap, hreflang, and country-name fallback Summary

**One-liner:** Wired `/zh/` (23 pages, English-aligned slugs) and `/de/` (23 pages, German ASCII-transliterated slugs) page trees end-to-end — Astro sitemap chunks, hreflang emission, root Accept-Language redirect, validate-seo coverage, and a `getLocalizedCountryName` helper with graceful EN fallback for snapshot data — yielding a clean `npm run build` exit 0 with 1892 pages built and 2186/2186 SEO checks passing.

## What Was Built

### 1. `getLocalizedCountryName(country, lang)` helper (src/lib/scores.ts)

Returns `country.name[lang] ?? country.name.en ?? ''`. Snapshot files (`data/scores/*.json`) currently contain `en/it/es/fr/pt` country names only; zh and de gracefully fall back to en until the pipeline is regenerated to emit those keys. The signature accepts `{ name: Record<string, string> }` so it works with both `ScoredCountry` and `CountryEntry` shapes.

### 2. Bulk migration of `country.name[lang]` to helper (src/, 80+ files)

Across `src/components/`, `src/lib/seo.ts`, `src/pages/{en,it,es,fr,pt}/`, and `src/pages/{zh,de}/`, every direct `country.name[lang]` access was replaced with `getLocalizedCountryName(country, lang)`. A Node script handled the bulk rewrite with regex-based per-file transforms and added the appropriate relative import. Patterns covered:
- `c.name[lang]`, `country.name[lang]`, `a.name[lang]`, `b.name[lang]` → simple var substitution
- `countries[0]?.name[lang]` → `(countries[0] ? getLocalizedCountryName(countries[0], lang) : '')` (badge files)
- `a.name[lang].localeCompare(b.name[lang])` (sort callbacks) → `getLocalizedCountryName(a, lang).localeCompare(getLocalizedCountryName(b, lang))`

`src/pipeline/config/countries.ts:getCountryName` was kept on direct access but its `lang` parameter widened to `'en' | 'it' | 'es' | 'fr' | 'pt' | 'zh' | 'de'` with a safe cast, since pipeline data only carries the original 5 locales.

### 3. Per-locale `Record<Lang, X>` literals updated to 7 entries

The 38-01 SUMMARY flagged 44 cascading TS errors from hardcoded `Record<Lang, X>` literals. This plan resolved them by adding zh and de keys to:
- `src/lib/seo.ts` — `localeMap`, `pillarLabels`, `riskLevels` (twice), homepage descriptions, global-safety names + descriptions, FAQ q1/q2/q3 + a1/a2/a3 templates, country meta description templates
- `src/components/country/AnswerFirstParagraph.astro` — `localeMap`, `pillarLabels`, `riskLevels`
- `src/components/country/StatsSummary.astro` — `riskLabels`, `templates` (full prose paragraph) + de-specific ordinal in `ordinal()`
- `src/components/country/ScoreHero.astro` — `verdicts.text` (now `Partial<Record<Lang>>` with en fallback in template)
- `src/components/country/RelatedCountries.astro` — `titles` (heading/region/similar)

Translation register matches 38-01: idiomatic Simplified Chinese (zh-CN) and standard High German (de-DE) with formal Sie.

### 4. Astro sitemap and i18n config (astro.config.mjs)

- Top-level `i18n.locales` array: `['en', 'it', 'es', 'fr', 'pt']` → adds `'zh', 'de'`
- `sitemap.i18n.locales` map gains `zh: 'zh'` and `de: 'de'`
- `sitemap.chunks` map gains zh and de splitter functions, producing `dist/client/sitemap-zh-0.xml` and `dist/client/sitemap-de-0.xml`
- `countryRouteSlugs` array gains `'land'` so the lastmod resolver extracts ISO3 from `/de/land/{iso3}/` URLs

### 5. Validation and ancillary scripts

- `scripts/validate-seo.ts`: `LANGUAGES` constant grows to 7 entries; `COUNTRY_SEGMENT` map adds `zh: 'country'` and `de: 'land'`; comment refreshed to "all 7 languages are present"
- `scripts/generate-llms-full.ts`: `ScoredCountry.name` interface widened to allow optional `zh?` / `de?` keys; descriptive copy updated to "Available in 7 languages (English, Italian, Spanish, French, Portuguese, Chinese, German)"

### 6. Cloudflare Pages Function root redirect (functions/index.ts)

`SUPPORTED_LANGS` extended from `['it', 'es', 'fr', 'pt', 'en']` to include `'zh', 'de'`. The Accept-Language parser already handles arbitrary 2-letter codes, so `zh-CN` → zh and `de-DE` → de start working immediately on first request to `/`.

### 7. Static fallback redirect page (src/pages/index.astro)

For non-Cloudflare runtime fallback:

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Promoted publishedLanguages to include zh+de**
- **Found during:** Final build verification
- **Issue:** Plan instructions did not explicitly mention re-flipping `publishedLanguages` after creating the page trees. Without it, hreflang would not emit for the new locales and the must_haves "Hreflang alternate links in every page <head> include both zh and de" would silently fail.
- **Fix:** Updated `src/i18n/ui.ts` `publishedLanguages` from `['en','it','es','fr','pt']` to `['en','it','es','fr','pt','zh','de']` and refreshed the inline comment to reflect that the page trees now exist.
- **Files modified:** src/i18n/ui.ts (-1 line stale comment, +6 lines updated)
- **Commit:** 0bdc4b2

**2. [Rule 1 - Bug] ScoreHero verdict text type tightened with safe fallback**
- **Found during:** Task 1 component migration
- **Issue:** `verdicts[verdictKey].text[lang]` previously read from `Record<Lang, string>` but the en literal only had en/it/es entries (other locales already missing). Adding 7-language coverage was straightforward, but to avoid future undefined renders if a new locale lands first, the type was loosened to `Partial<Record<Lang, string>>` and the template now reads `verdict.text[lang] ?? verdict.text.en`.
- **Files modified:** src/components/country/ScoreHero.astro
- **Commit:** 8129b30

**3. [Rule 2 - Critical] Build cache eviction required before fresh build succeeded**
- **Found during:** First post-changes build attempt
- **Issue:** First `npm run build` failed with `ERR_MODULE_NOT_FOUND` for `_slug__BR57Jemv.mjs` due to stale `dist/` and `node_modules/.vite` caches referencing the previous (5-language) chunk graph.
- **Fix:** Cleared `dist`, `node_modules/.vite`, `node_modules/.astro` then re-ran build. Build then completed cleanly in 450s with 1892 pages and exit 0.
- **No source changes** — operational issue only. Documenting because future contributors regenerating the build after similar large structural changes should know to clear caches.

**4. [Out of scope]** No data-pipeline changes were made to add zh/de country names to snapshots. The `getLocalizedCountryName` helper falls back to en for both locales, which produces correct, readable pages today. Adding pipeline-side translations is deferred to a future plan if/when machine-readable country-name sources for zh and de are wired in.
