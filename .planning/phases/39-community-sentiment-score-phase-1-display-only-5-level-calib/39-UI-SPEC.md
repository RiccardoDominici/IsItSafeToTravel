# Phase 39 — UI Design Contract

> Visual and interaction contract for the Community Sentiment feature (Phase 1, display-only).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> **This site has a mature production design system.** Every value below is derived from the
> existing codebase (`src/styles/global.css`, `src/components/country/*`) — nothing is invented.
> No new fonts, no new colors, no new component library.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (custom Astro 6 SSG + Tailwind v4 CSS-first `@theme`; no `components.json`, no shadcn) |
| Preset | not applicable |
| Component library | none — hand-authored `.astro` components, no React/Radix/Base-UI |
| Icon library | inline hand-authored SVG (`stroke-width="2"`, `viewBox="0 0 24 24"` for line icons; `viewBox="0 0 16 16"` `fill="currentColor"` for small solid glyphs; `role="img"` + `aria-label` on informative SVGs) |
| Font | Body: **Inter Variable** (`--font-sans`). Headings: **DM Sans Variable** (`--font-heading`). Both variable, latin + latin-ext only; zh falls back to system CJK. |

**Client-script pattern (load-bearing for the vote widget):** no framework. Behavior is added
with a plain inline `<script>` that queries the DOM by `id`, attaches listeners, and re-inits on
`astro:after-swap` (see `src/components/DarkModeToggle.astro`). State persists in `localStorage`
only (no cookies). This is the exact pattern the vote widget must follow (D-18).

## Spacing Scale

Tailwind default 4px grid, plus three named custom tokens from `@theme`. All values are multiples of 4.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | icon gaps, tight inline padding |
| sm | 8px (`gap-2`) | gap between radio option and its label; chip padding-x |
| — | 12px (`gap-3`) | pillar row gap (label ↔ bar ↔ value) — matches existing `PillarBreakdown` |
| md | 16px (`p-4`, `mb-4`) | card interior padding; section title bottom margin |
| lg | 24px (`py-6`, `--spacing-card`) | section vertical padding; card block rhythm |
| xl | 32px (`py-8`, `space-y-8`) | vertical gap between top-level country-page sections |
| 2xl | 48px (`--spacing-section`) | major section breaks |
| 3xl | 64px (`--spacing-header`) | page-level / header spacing |

Exceptions:
- **44px minimum touch target** is enforced globally in `global.css` on `a, button, [role="button"], summary, input, select, textarea`. Every radio option, label, and the submit button in the vote widget MUST meet 44px min-height (inline text links are exempt via the `p a, li a…` override — do not put the vote controls inside flowing text).

## Typography

Roles below cover this phase's surfaces (Sentiment pillar card, vote widget, methodology/privacy prose). Sizes are the site's live Tailwind classes.

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Section heading (H2) | 20px → 24px (`text-xl md:text-2xl`) | 700 bold, `font-heading` (DM Sans) | ~1.2 | Sentiment card title, methodology H2 — mirrors `PillarBreakdown` H2 exactly |
| Widget question (legend) | 16px (`text-base`) | 600 semibold | 1.4 | the "Does this score feel right?" prompt |
| Body / prose | 16px (base, `html { font-size:16px }`) | 400 regular, Inter | 1.5 | methodology + privacy paragraphs |
| Label / value / meta | 14px (`text-sm`) | 400 labels · 500 numeric values | 1.5 | pillar label, "X.X/10", radio option labels |
| Micro / caption | 12px (`text-xs`) | 400 regular | 1.4 (`leading-snug`) | correction "+0.4 vs official", vote count, disclaimer, tooltip body |

**Weights:** primary pair is **regular 400** + **bold 700** (the greenfield default). This mature
site additionally uses **medium 500** (numeric values, buttons) and **semibold 600** (badges,
subheads, the widget legend) — these are established system weights, reused here, **not** new
additions. Variable fonts make the extra axes free.

Color of text follows the site convention: headings `text-sand-800 dark:text-sand-100`; body
`text-sand-700 dark:text-sand-200`; muted/meta `text-sand-600 dark:text-sand-400` and
`text-sand-500` for the quietest captions.

## Color

Palette is OKLCH, defined in `src/styles/global.css` `@theme`. **Do not introduce any color
outside this palette** (team-lead constraint). The 60/30/10 split maps to the site's neutral
`sand` ramp for surface/secondary and `terracotta` for accent; the safety **score gradient** is
a separate data-visualization scale and is intentionally excluded from the 10% accent budget.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `sand-50` / white (light), `sand-900` (dark) | page background; body text `sand-800`/`sand-100` |
| Secondary (30%) | card surface `bg-white dark:bg-sand-800`; borders `border-sand-200 dark:border-sand-700`; muted text `sand-600`/`sand-400`/`sand-500` | Sentiment card chrome, dividers, meta text, the neutral "Community" badge (`bg-sand-100 dark:bg-sand-700 text-sand-700 dark:text-sand-200`) |
| Accent (10%) | `terracotta-500` (hover `terracotta-600`); focus outline `#c2410c` (terracotta-700) | see reserved-for list below |
| Destructive | not applicable | no destructive actions in this phase (voting is additive; localStorage dedupe is not user-facing deletion) |

**Accent (`terracotta`) reserved for — exhaustive list:**
1. The **Submit vote** primary button (`bg-terracotta-500 hover:bg-terracotta-600 text-white`).
2. Inline text **links** added by this phase (methodology ↔ privacy cross-references, "learn how this works" link).
3. The global keyboard **focus outline** (`2px solid #c2410c`, offset 2px) — inherited, do not override.

Accent is **not** used for the pillar bar, the badge, or selected-radio fill.

**Data-viz scale (separate from accent, reserved for the Sentiment bar only):** the shared safety
score gradient `scoreToColor()` / `pillarToColor()` from `src/lib/colors.ts` — blue `#4a7fbf`
(safe/10) → yellow `#d4b83c` (5.5) → red `#9e3a2a` (danger/1). The Sentiment value bar fill MUST
use this scale at the community-perceived 1–10 value, exactly like the other five pillars, so the
sixth pillar reads as "same visual weight." The "Community" badge deliberately uses a **neutral
sand** chip (never a safety-gradient hue) so it cannot be misread as a risk level.

**Contrast:** all pairings above are the site's existing WCAG 2.1 AA tokens from Phase 20 (4.5:1
text, 3:1 large/UI) in both light and dark mode. Selected/checked state MUST NOT rely on color
alone (WCAG 1.4.1): use the native radio dot + a `bg-sand-100 dark:bg-sand-700` fill + bolder
label on the chosen option.

## Component Inventory

Three UI surfaces + two text-only doc additions. Reuse existing chrome; add no new primitives.

### 1. Sentiment pillar (the "6th pillar")
- **Goal:** appears alongside conflict/crime/health/governance/environment with the **same visual
  weight** (D-04), yet is unambiguously flagged as community-sourced and **display-only, weight 0,
  does not affect the total** (D-06).
- **Bar (invariant — identical to the other five):** reuse the `PillarBreakdown` row anatomy —
  label (`w-28 shrink-0 text-sm text-sand-600 dark:text-sand-400 text-right`) · SVG bar
  (`viewBox="0 0 200 24"`, `h-6`, track `rect` fill `text-sand-200 dark:text-sand-700`, value
  `rect` fill = score gradient at the perceived value, width = `perceivedValue/10 * 180`,
  `role="img"` `aria-label="Sentiment: X.X/10 (community estimate)"`) · value
  (`w-14 shrink-0 text-sm font-medium`, `"X.X/10"`).
- **Community metadata (attached to this row / its containing card):**
  - a neutral **"Community" badge** — `inline-flex items-center gap-1 px-2 py-0.5 rounded-full text-xs font-semibold bg-sand-100 dark:bg-sand-700 text-sand-700 dark:text-sand-200` (mirrors the "updated daily" badge geometry).
  - the **correction**, e.g. `+0.4 vs official` — `text-xs font-medium`, sign always shown, `text-sand-600 dark:text-sand-400`.
  - the **vote count**, e.g. `based on 37 votes` — `text-xs text-sand-500 dark:text-sand-400`.
  - a persistent **disclaimer** line: `text-xs text-sand-500 dark:text-sand-400`, plain (not red, not a warning) — "Community estimate — does not affect the safety score." A `PillarCoverageTip`-style tooltip MAY carry the longer explanation, but the short disclaimer stays visible (transparency is a core project value; do not hide it behind a hover-only tooltip).
- **Recommended placement/structure:** render the Sentiment value as the 6th bar row (for visual
  parity) and wrap the badge + correction + vote count + disclaimer as a sub-line beneath it, all
  inside one bordered panel (`rounded-lg border border-sand-200 dark:border-sand-700 p-4 bg-white
  dark:bg-sand-800`) placed **immediately after the `#pillars` section** (D-17: near the score /
  pillars). The card border is the only additive chrome beyond the plain pillar rows and is
  justified because this pillar uniquely carries interactive + community context. The vote widget
  (below) lives inside this same panel, under a `border-t border-sand-200 dark:border-sand-700`
  divider.

### 2. Five-level calibration vote widget
- Sits inside the Sentiment panel, below the pillar display (D-17).
- **Semantics:** a `<form>` (no navigating `action`) → `<fieldset>` → `<legend>` (the question) →
  five native `<input type="radio" name="calibration">` inside `<label>`s → submit `<button>`.
  Native radios give free arrow-key navigation and a screen-reader-announced group. `accent-color:
  var(--color-terracotta-500)` on the radios themes the native control without new markup.
- **Options (order top→bottom or left→right, D-02) with their stored signed delta:**
  | Label (score-relative) | Delta | Meaning |
  |---|---|---|
  | Way too high | −2 | community thinks it's *less* safe |
  | Too high | −1 | |
  | About right | 0 | |
  | Too low | +1 | |
  | Way too low | +2 | community thinks it's *more* safe |
  Each option row is min-height 44px, `text-sm`, radio + label `gap-2`; selected option gets
  `bg-sand-100 dark:bg-sand-700 rounded-md` + `font-medium` (non-color-only selection cue).
- **Submit button:** primary accent — `bg-terracotta-500 hover:bg-terracotta-600 text-white
  font-medium rounded-md px-3 py-1.5 transition-colors` (matches `TravelDealsWidget` button),
  disabled until an option is chosen.
- **Progressive enhancement (D-18):** the submit control is JS-gated — render it with `hidden`
  removed by the inline script on init (`document.addEventListener('astro:after-swap', init)`),
  so that with JS disabled the widget cannot half-submit and the page is unaffected (silent
  degradation). On submit: `preventDefault` → `fetch('/api/vote', {method:'POST', …})` → on success
  swap to thank-you state; on failure show the muted error line and leave options intact.
- **localStorage soft dedupe:** key `sentiment-voted-<ISO3>`. On init, if present, render the
  thank-you/"already voted" state instead of the prompt (D-17). No cookies.

### 3. Widget interaction states
| State | Trigger | What renders |
|-------|---------|--------------|
| Prompt (default) | fresh visit, JS on, not yet voted | question + 5 options + (revealed) submit |
| Below-floor / empty | aggregate has `< 5` votes (D-09) | the "not enough votes yet" message **in place of the bar+value**, with the prompt widget still shown to invite the first votes |
| Thank-you | successful POST, or `localStorage` flag present | thank-you heading + body; prompt controls removed; not re-prompted |
| Error (silent, muted) | fetch rejects / endpoint down | quiet inline line (sand-500, **no red, no alert role that steals focus**); options remain; page otherwise untouched |
| No-JS | JS disabled | pillar display renders normally; submit stays `hidden`; no broken control |

### 4. Methodology page section (text-only, D-19)
Reuse existing methodology prose styling (H2 `text-xl md:text-2xl font-heading font-bold`, body
16px/1.5). New section: how community calibration works, the five levels, the ±1.0-point cap, and
an **explicit statement that in Phase 1 it does NOT affect the total score.** No new components.

### 5. Privacy page addition (text-only, D-20)
One short paragraph in existing prose style: salted-hash dedupe, **no raw IP retention**, Turnstile
only when enabled, and a `localStorage` (soft dedupe) note kept honest against the zero-cookie
claim. No new components.

## Accessibility (WCAG 2.1 AA — Phase 20 baseline)

- **Group semantics:** `<fieldset>` + `<legend>` (or `role="radiogroup"` + `aria-labelledby` on the question) so the 5 options are announced as one labelled group.
- **Keyboard:** native radios provide arrow-key selection; submit is a real `<button>`; all controls ≥ 44px. Tab order: options → submit.
- **Focus:** inherit the global `:focus-visible` outline (`2px solid #c2410c`, offset 2px) — do not suppress.
- **Selection cue:** not color-only — native radio dot + `bg-sand-100/dark:bg-sand-700` + `font-medium` on the chosen label.
- **Live regions:** the thank-you / error swap should live in a container with `aria-live="polite"` so the outcome is announced without moving focus. The error must **not** use `role="alert"` (would steal focus / conflict with "silent degradation").
- **SVG bar:** `role="img"` + localized `aria-label` (value + "community estimate"), matching existing pillar bars.
- **Contrast:** both modes use existing AA-verified `sand`/`terracotta` pairings; the neutral badge and muted meta text keep ≥ 4.5:1 on their surfaces.
